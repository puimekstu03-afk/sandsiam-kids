# SANDSIAM Kids · ก่อเจดีย์ทรายวันสงกรานต์ (ฉบับการ์ตูนสำหรับเด็ก)

SANDSIAM เวอร์ชันสำหรับนักเรียนประถม 1–6 หน้าตาเป็นการ์ตูนน่ารัก มีเส้นขอบหนา ใช้สีสดใส และปุ่มที่กดแล้วยุบลงเหมือนของเล่น ส่วนฉากของทั้ง 5 ภาคเป็นภาพวาดการ์ตูนแบบลงสีนุ่ม ๆ
ใช้งานได้ 3 ภาษา (ไทย · English · 中文) และไม่ต้อง build ก่อนใช้งาน

> โฟลเดอร์ต้นฉบับ `../sandsiam/` ยังอยู่ครบ ไม่ได้แก้ไขอะไร

## วิธีเปิดใช้งาน

```sh
python3 -m http.server 8767 --directory public
```

จากนั้นเปิด http://localhost:8767 (หรือใช้ค่า `sandsiam-kids` ใน `.claude/launch.json` ที่อยู่โฟลเดอร์บนสุด)

## สิ่งที่เปลี่ยนจากฉบับเดิม

- **ฉากการ์ตูนแบบภาพวาด**: ฉากของทั้ง 5 ภาคเป็นภาพวาดการ์ตูนลงสีนุ่ม แทนรูปทรงที่วาดด้วยโค้ด (ฉบับเดิมเก็บไว้ใน `_backup_cartoon/`)
  - ภาคเหนือ: วิหารล้านนา เจดีย์ทอง ตุง และดอย · ภาคกลาง: โบสถ์กับพระปรางค์และลีลาวดี · ภาคอีสาน: ปราสาทบนเขากับนาข้าว ต้นตาล · ภาคตะวันออก: ชายหาดกับเกาะ · ภาคใต้: เจดีย์ขาวริมทะเลยามเย็น
  - เจดีย์ในลานยืนเฉพาะบนพื้นทราย จัดเป็น 3 แถว (3 · 4 · 5 องค์) แถวกลางอยู่ในช่องว่างของแถวหน้า แถวหลังเรียงห่างเท่ากันเหนือยอดแถวกลาง จึงไม่บังกัน และเล็กลงตามระยะไกล
  - เจดีย์ลงแสงสีและเงาตามทิศแสงของแต่ละฉาก ไม่มีเส้นขอบหนาหรือขอบขาวแบบสติกเกอร์ เจดีย์ตัวอย่างวางพวงดอกไม้แนบชั้น และปักธงบนพื้นทรายสองข้าง
- **UI การ์ตูน**: เส้นขอบสีม่วงเข้ม เงาแข็งแบบของเล่น ปุ่มกลมใหญ่ และสีประจำแต่ละขั้นและแต่ละภาค แผงด้านขวาลอยเป็นการ์ดกระดาษลายจุด
- **ฟอนต์สำหรับเด็ก**: ทั้งหัวข้อและเนื้อหาใช้ Mali (ลายมือเด็ก ตัวกลมมน มีหัว แบบที่เด็กเรียนในโรงเรียน) ภาษาจีนใช้ ZCOOL KuaiLe สำหรับหัวข้อ และ Noto Sans SC สำหรับเนื้อหา
- **ของตกแต่ง 40 ชิ้น**: จากภาพถ่าย 9 ชิ้น เปลี่ยนเป็นภาพการ์ตูนสไตล์เดียวกับเจดีย์ (เส้นขอบน้ำตาล ผิวมันวาว) แบ่ง 4 แท็บ: ของบูชา ดอกไม้ ของไทย ของน่ารัก
  - สีแรกในจานสีคือ "สีจริงของภาพ" (วงกลมสีรุ้ง) ซึ่งเป็นสีเริ่มต้น ถ้าเลือกสีอื่น ระบบจะเปลี่ยนสีหลักของภาพให้ ส่วนธงชาติ เทียน มะลิ และขันน้ำคงสีเดิม
  - ดอกไม้ 11 แบบ (ดาวเรือง บัว กุหลาบ มะลิ ทานตะวัน ชบา ลีลาวดี กล้วยไม้ บานไม่รู้โรย ดอกเข็ม ดาวกระจาย) เป็นดอกเดี่ยว ไม่มีก้านและใบ ลงสีไล่เฉดแบบกึ่งเหมือนจริง วาดด้วย SVG ใน `tools/flowers/flowers.html` (เปิดไฟล์ตรง ๆ เพื่อดูทุกดอก) แล้วรัน `python3 tools/flowers/render.py` เพื่อบันทึกเป็นภาพ (ต้องมี Google Chrome) ดอกเข็มและดาวกระจายใช้เลขชิ้นเดิมของช่อดอกไม้และกระถางดอกไม้
  - สร้อยดอกไม้รอบชั้น 9 แบบ: ดาวเรือง (สีขาวนวลเป็นมะลิ) · ดาวเรืองสลับมะลิ · มะลิ · กุหลาบ · บานไม่รู้โรย · ดอกเข็ม · ดาวกระจาย · ลีลาวดี · หลากสี แต่ละแบบเป็นรายการใน `ORNAMENTS` ที่มี `ring: [ดอก, ...]` ร้อยจากภาพดอกเล็ก `ring-<ดอก>.webp` สลับกันตามลำดับ
  - ภาพอื่นสร้างด้วย Canva เป็นแผ่นละ 6 ชิ้นบนพื้นขาว แผ่นต้นฉบับอยู่ใน `stickers-src/` และงานออกแบบ "SANDSIAM stickers" ในบัญชี Canva
  - **วิธีเพิ่มชิ้นใหม่**:
    1. ทำแผ่นสติกเกอร์สไตล์เดียวกันบนพื้นขาว
    2. รัน `python3 tools/cut-stickers.py แผ่น.png ชื่อ1,ชื่อ2,...` (ธงที่มีเสาสูงใส่ `640` ต่อท้าย)
    3. ต่อท้าย `ORNAMENTS` ใน `catalog.js` เสมอ เพราะงานที่บันทึกไว้อ้างอิงเลขประจำชิ้น
    4. เพิ่มชื่อใน `items` ทั้ง 3 ภาษา
    5. ใส่เลขลงแท็บใน `TAB_ITEMS` (`js/app/config.js`)
- **แผงชั้นของตกแต่ง** (ขั้นตกแต่ง): อยู่ด้านขวาของฉาก แทนส่วน "ปรับละเอียด" แบบเดิม
  - แสดงทุกชิ้นเรียงจากหน้าสุดไปหลังสุด และมี "เจดีย์ทราย" อยู่ในรายการด้วย
  - ลากที่จุดจับ หรือกดลูกศรขึ้น-ลง เพื่อย้ายชั้น ถ้าย้ายลงเลยแถวเจดีย์ ชิ้นนั้นจะไปอยู่หลังเจดีย์
  - ชิ้นที่เลือกปรับขนาด เลื่อนตำแหน่ง และลบได้ในแผงเดียวกัน
  - การย้ายชั้นกดปุ่ม "ย้อน" ได้ และบันทึกไว้กับงาน
  - พับเก็บได้ด้วยปุ่มกลม บนมือถือแผงจะอยู่ในแผงด้านล่าง
- **ไอคอนแทนอิโมจิ**: ทั้งหน้าไม่มีอิโมจิแล้ว ใช้ไอคอน [Lucide](https://lucide.dev) (สัญญาอนุญาต ISC) แทน
  - ไอคอนทุกตัว (แถบบน ปุ่มย้อนกลับ/ทำซ้ำ แถบขั้นตอน ปุ่มเลื่อน ปุ่มปิด ฯลฯ) คัดลอกจากไฟล์ของ Lucide 1.59.0 ตรง ๆ เก็บรวมไว้ใน `<svg class="icon-sprite">` ตอนต้นของ `index.html` และแต่ละ `<symbol>` มีคอมเมนต์บอกชื่อไอคอนบน lucide.dev
  - ยกเว้น 2 อย่าง: `i-music-off` ใช้ไอคอน music แล้วขีดทับด้วยเส้นแบบไอคอน "-off" ของ Lucide (Lucide ไม่มี music-off) และโลโก้ LINE / Facebook / X ในแถบแชร์ที่ซ่อนอยู่ เพราะ Lucide ไม่มีโลโก้แบรนด์
  - ในโค้ดเรียกด้วย `icon('ชื่อ')` ใน `js/app/main.js` ไอคอนแถบขั้นตอนตั้งชื่อไว้ใน `STEP_ICONS` (`js/app/config.js`)
  - ถ้าจะเพิ่มไอคอน ให้คัดลอก path จาก lucide.dev มาเพิ่มเป็น `<symbol id="i-ชื่อ">`
- **แยกไฟล์ละเอียด**: CSS 1 ไฟล์แยกเป็น 28 ไฟล์ และ JS 6 ไฟล์แยกเป็น 23 ไฟล์ตามหน้าที่ ฟีเจอร์และข้อมูลที่บันทึกไว้ยังเหมือนเดิมทั้งหมด

- **หน้าแรกมีชีวิตชีวา**: พลุสีสดจุดเองเป็นระยะทางสองข้างของป้ายชื่อ ดาวระยิบรอบป้าย และตัวอักษร SANDSIAM เด้งเป็นคลื่น แตะที่ฉากเพื่อจุดพลุตรงจุดนั้นได้ (`js/kids/intro-fx.js`) ทั้งหมดหยุดเมื่อผู้ใช้ตั้งค่าลดการเคลื่อนไหว
- **เพลงประกอบเบา ๆ**: เล่นไฟล์ `public/assets/music/songkran.m4a` (ท่อนยาว 3 นาทีครึ่ง แบบ mono AAC ขนาดราว 1.7 MB) วนซ้ำเบา ๆ ตลอดเวลาทุกหน้าจอ (`js/kids/music.js` ปรับความดังที่ `VOLUME`) พยายามเล่นเองทันทีที่เปิดหน้า ถ้าเบราว์เซอร์บล็อกเสียงก่อนผู้ใช้แตะ เพลงจะเริ่มเมื่อแตะหรือกดปุ่มใด ๆ ครั้งแรก (ระหว่างรอ ปุ่มโน้ตเพลงที่แถบบนจะส่ายเชิญให้แตะ) ปุ่มโน้ตเพลงใช้เปิด-ปิด และจำค่าไว้
  - ให้เพลงขึ้นเองโดยไม่ต้องแตะ (บน Mac): ดับเบิลคลิก `tools/open-in-chrome.command` จะเปิด Chrome หน้าต่างแยกที่ปิดกฎบล็อกเสียงไว้ เพลงเล่นทันทีที่หน้าเปิด (ใช้โปรไฟล์ Chrome แยกของตัวเอง ชื่อผู้เล่นและสติกเกอร์จำไว้ในโปรไฟล์นั้น)
  - ตัดมาจากไฟล์เต็ม 43 นาที (46 MB ซึ่งใหญ่เกินกว่าจะให้เด็กทุกคนโหลด) ด้วย `python3 tools/make-music-loop.py "../รวมเพลงสงกรานต์บรรเลง แบบไทยไทย.mp3"` ถ้าจะเปลี่ยนเพลงหรือเลือกท่อนใหม่ ให้รันคำสั่งนี้กับไฟล์ใหม่ (ใส่วินาทีเริ่มและจบต่อท้ายได้)
  - ต้องมีสิทธิ์ใช้เพลงก่อนเผยแพร่เว็บต่อสาธารณะ

## ฐานข้อมูลลานเจดีย์ (Supabase)

ข้อมูลเจดีย์ รูปเจดีย์ และจำนวนคนที่เข้ามาเล่น เก็บไว้ในโปรเจกต์ Supabase ชื่อ `sandsiam` (ภูมิภาคสิงคโปร์ แพ็กเกจฟรี) หน้าแรกแสดงตัวนับ "ก่อเจดีย์แล้ว N องค์"

- **เด็กไม่ต้องล็อกอิน**: แต่ละเบราว์เซอร์มีรหัสเครื่องแบบสุ่ม และเด็กแต่ละคนในเครื่องนั้นมีรหัสผู้เล่น 1 แถวในฐานข้อมูลคือเจดีย์ของเด็ก 1 คนใน 1 ภาค ถ้าถวายซ้ำในภาคเดิม ระบบจะแทนที่เจดีย์องค์เดิม
- **เปิดกว้าง ไม่ต้องใส่รหัสใด ๆ**: เจดีย์ขึ้นลานทันทีที่ถวาย หลังผ่านตัวกรองคำไม่สุภาพ ซึ่งตรวจทั้งในแอป (`js/kids/polite.js`) และในฐานข้อมูล (`private.is_polite`) ถ้าแก้รายการคำ ต้องแก้ทั้งสองที่ให้ตรงกัน คำปกติที่บังเอิญมีคำหยาบซ้อนอยู่ เช่น ห่างไกล สกู๊ตเตอร์ แม่งาน ใส่ไว้ในรายการ `FINE`
- **ข้อมูลเจดีย์** (ตาราง `pagodas`): รูปแบบเจดีย์ ชื่อเล่น คำอวยพร ภาค และเวลาที่ถวาย คนอื่นเห็นเจดีย์ผ่านรหัสสุ่ม (`public_id`) ไม่เห็นรหัสเครื่อง
- **รูปเจดีย์** (Storage bucket `pagoda-images`): ตอนถวาย แอปสร้างรูป JPEG ขนาด 960×840 (ราว 100–150 KB รับได้ไม่เกิน 400 KB) แล้วส่งไปพร้อมเจดีย์ ชื่อไฟล์อยู่ในช่อง `image_path` ถ้าถวายซ้ำ รูปเก่าจะถูกลบ และรูปที่ไม่มีเจดีย์ใช้จะถูกเก็บกวาดเป็นระยะ ถ้าส่งรูปไม่สำเร็จ เจดีย์ยังขึ้นลานได้ตามปกติ
- **คนที่เข้ามาเล่น** (ตาราง `visits`): บันทึกวันละ 1 แถวต่อเครื่องและผู้เล่น แยกเป็น `open` (เปิดหน้าเว็บ) และ `play` (เริ่มก่อเจดีย์) ช่อง `hits` นับจำนวนครั้ง แต่ละแท็บบันทึกแค่ครั้งเดียว ข้อมูลที่เก่ากว่า 120 วันจะถูกรวมเป็นยอดรายวันในตาราง `private.daily_visits` ทุกคืน (pg_cron)
- **ลานเต็มแล้วเปิดลานใหม่**: แต่ละภาคมีลานละ 12 องค์ (`FIELD_SIZE` ใน `js/scene/field.js`) เจดีย์แต่ละองค์ได้เลขประจำภาค (`seq`) ตั้งแต่ถวายครั้งแรก องค์ที่ 1–12 อยู่ลานที่ 1 องค์ที่ 13–24 อยู่ลานที่ 2 ไปเรื่อย ๆ เลขนี้ไม่เปลี่ยน ถวายซ้ำหรือซ่อนองค์อื่นไปก็ยังอยู่ลานเดิม (องค์ที่ถูกซ่อนจะเว้นช่องว่างไว้) ทุกคนกดลูกศรชมได้ทุกลาน เปิดหน้าลานจะเห็นลานล่าสุด แต่ถ้ามาจากเจดีย์ของตัวเองจะเห็นลานที่เจดีย์ของตัวเองอยู่ เจดีย์ตัวอย่างเติมเฉพาะลานที่ 1 (ฟังก์ชัน `field_page`) แอปเช็กตัวเลขทุก 30 วินาที และโหลดลานใหม่เฉพาะตอนที่มีเจดีย์เปลี่ยน
- **ตัวนับ**: หน้าเว็บแสดงเฉพาะจำนวนเจดีย์ในลาน ส่วนจำนวนคนที่เข้ามาเล่นเก็บไว้ดูหลังบ้าน (`daily_stats`) ไม่เก็บ IP อีเมล หรือชื่อจริง (IP ใช้เพียงนับเพดานกันสแปม โดยเก็บเป็นค่า hash ที่ผสมรหัสลับ และลบทิ้งหลัง 1 วัน)
- **ถ้าฐานข้อมูลปิดพัก**: ลานจะขึ้นข้อความว่า "ลานเจดีย์ออนไลน์ปิดพักอยู่" และซ่อนตัวนับไว้ เด็กยังก่อเจดีย์และเก็บรูปได้ตามปกติ
- **ดูสถิติ** (Table Editor > schema `private`): `daily_stats` แสดงจำนวนรายวัน (เครื่องที่เปิดหน้าเว็บ · เด็กที่เล่น · เจดีย์ที่ถวาย) ส่วน `pagodas_with_pictures` แสดงเจดีย์ทุกองค์พร้อมลิงก์รูป
- **ความปลอดภัย**: คีย์สาธารณะใน `supabase-store.js` ใช้ได้แค่ *อ่าน* ลาน การเขียนทุกอย่าง (ถวายเจดีย์พร้อมรูป และบันทึกการเข้าเล่น) ต้องผ่าน Edge Function `field` (`supabase/functions/field/index.ts`) เท่านั้น ฟังก์ชันนี้รู้ IP จริงของผู้ส่ง (`cf-connecting-ip` ปลอมไม่ได้) และฐานข้อมูลจำกัดจำนวน:
  - ถวายเจดีย์: ต่อ IP ไม่เกิน 120 ครั้งต่อนาที, 300 ครั้งต่อชั่วโมง, 800 ครั้งต่อวัน (เผื่อทั้งโรงเรียนใช้ IP เดียวกัน ทั้งห้องกดพร้อมกันได้) และรวมทุกคนไม่เกิน 300 ครั้งต่อนาที ถ้าชนเพดานรายนาที แอปจะรอแล้วลองใหม่ให้เอง 3 ครั้ง
  - บันทึกการเข้าเล่น: ต่อ IP ไม่เกิน 1,500 ครั้งต่อชั่วโมง รวมทุกคนไม่เกิน 1,000 ครั้งต่อนาที (เกินแล้วข้ามไปเงียบ ๆ)
  - เจดีย์ทั้งหมดไม่เกิน 20,000 องค์
  - ปรับตัวเลขได้ที่ `private.allow` (ฉบับล่าสุดใน `supabase/migrations/20261019070000_class_friendly_limits.sql`)
  - ยังมีช่องโหว่เหลืออยู่: คนที่ใช้ IP จำนวนมากยังส่งได้มากกว่านี้ ถ้าเจอปัญหาจริง ให้เพิ่ม Cloudflare Turnstile (ต้องสมัครบัญชี Cloudflare)
- **ซ่อนเจดีย์ที่ไม่เหมาะสม**: ทำได้เฉพาะเจ้าของโปรเจกต์ ผ่าน Supabase dashboard > Table Editor > `pagodas` > แก้ช่อง `status` เป็น `hidden` เจดีย์ที่ซ่อนแล้วจะไม่กลับขึ้นลาน แม้เด็กจะถวายซ้ำ
- **ไฟล์**: `supabase/migrations/` (โครงสร้างฐานข้อมูล) · `supabase/functions/field/` (Edge Function สำหรับเขียน) · `public/js/store/supabase-store.js` (ที่อยู่โปรเจกต์ คีย์สาธารณะ และการเรียกฟังก์ชัน) ส่วนรหัสผ่านฐานข้อมูลอยู่ใน `supabase/.db-password` ห้ามเผยแพร่ไฟล์นี้
- **อัปเดตฐานข้อมูลและ Edge Function**: `supabase db push` และ `supabase functions deploy field --use-api` (ไม่ต้องมี Docker)
- **สำรองข้อมูล**: แพ็กเกจฟรีไม่มี backup ให้กู้คืนเอง รัน `sh tools/backup-db.sh` เป็นระยะ (อย่างน้อยก่อนและหลังช่วงสงกรานต์) ไฟล์จะอยู่ใน `backups/` ซึ่งมีชื่อเล่นและคำอวยพรของเด็ก จึงตั้งไว้ไม่ให้ขึ้น git (รูปเจดีย์ใน Storage ไม่ได้อยู่ในไฟล์นี้)
- **กันโปรเจกต์ถูกพัก (keep-alive)**: Supabase แพ็กเกจฟรีจะพักโปรเจกต์ที่ไม่มีคนใช้ 7 วัน ซึ่งเกิดได้ง่ายนอกช่วงสงกรานต์ ทางแก้มี 3 แบบ
  1. push โฟลเดอร์นี้ขึ้น GitHub แล้ว `.github/workflows/keepalive.yml` จะรัน `tools/keepalive.sh` ให้ทุก 3 วัน
  2. ตั้งให้เครื่องที่เปิดเป็นประจำรัน `sh tools/keepalive.sh` ทุก 2–3 วัน
  3. อัปเกรดเป็นแพ็กเกจ Pro (ไม่ถูกพัก และมี backup)
  - ถ้าโปรเจกต์ถูกพักไปแล้ว ให้เข้า Supabase dashboard แล้วกด Restore ก่อนถึงงาน
- ถ้าลบค่า `SUPABASE.url` ใน `supabase-store.js` แอปจะกลับไปใช้ฐานข้อมูลของ claude.ai Artifact หรือเก็บในเครื่องเหมือนเดิม

## หมายเหตุ

- งานที่บันทึกไว้ใช้ key ใน localStorage ชุดเดิม (`sandsiam-*`) ถ้าเปิดจาก origin เดียวกันกับฉบับเดิม จะเห็นงานเดิมต่อได้
- `ARTIFACT_URL` ใน `js/app/config.js` ยังชี้ไปที่ Artifact ฉบับเดิม ถ้าจะเผยแพร่ฉบับนี้เป็น Artifact ใหม่ ให้เปลี่ยนเป็นลิงก์ใหม่ก่อน
- เผยแพร่: รัน `python3 tools/build-artifact.py` แล้วเผยแพร่ `public/artifact.html` โดยใช้ `public` เป็น root พร้อมไฟล์ใน `css/` `js/` และ `assets/`
